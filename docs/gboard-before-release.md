# G-board, 배포 전에

이 문서는 선생님용이 아니다. 만드는 사람용이다. 설치 파일을 이 기기
밖으로 내보내기 전에 참이어야 하는 것들을 적는다. 2판 이후에 할 일
(`docs/superpowers/plans/`)과는 별개로, **1판 설치형을 처음 내보낼 때**
반드시 짚어야 하는 목록이다.

## 닫은 것

- **개발자 도구.** 2판 동안만 켜기로 했던 것을 3판에서 껐다
  (`features = []`). 켜져 있으면 키보드 앞의 누구나
  `window.__TAURI__.core.invoke(...)`로 파일 삭제 명령을 화면을 거치지 않고
  직접 부를 수 있었다 — 단일 인스턴스 잠금이 막으려던 자료 손실이 다른
  문으로 열리는 셈이고, 교실 컴퓨터는 아이들이 앉는 자리다.

  **글로만 적어 두지 않는다.** 2판 내내 켜져 있었고 그걸 붙들고 있던 것은
  이 문서의 한 문단뿐이었다. `scripts/check-release.mjs`가 이제 센다.
  `npm run desktop:build`가 그 검사를 먼저 돌리므로 **켜진 채로는 설치
  파일이 안 만들어진다.** 검사가 함께 보는 것:

  | | |
  |---|---|
  | 개발자 도구 | 꺼져 있는가 |
  | CSP | 비어 있지 않은가 (`null`은 "느슨한 CSP"가 아니라 없다는 뜻이다) |
  | 판 번호 | `package.json`·`tauri.conf.json`·`Cargo.toml` 셋이 같은가 |
  | 바깥 주소 | 실제로 부르는 두 곳뿐인가 |


- **단일 인스턴스 잠금.** 앱을 두 번 띄우면 두 인스턴스가 각자 자료
  전체를 메모리에 들고 같은 `data.json`을 통째로 덮어써, 선생님이
  바탕화면 아이콘을 두 번 눌렀을 뿐인데 1년치 기록이 경고 한 줄 없이
  사라질 수 있었다. `tauri-plugin-single-instance`를 다른 모든
  `.plugin(...)`보다 먼저 등록해, 두 번째로 뜬 프로세스가 `data.json`을
  열어보기도 전에 곧장 끝나고 이미 켜진 창만 앞으로 불러오게 막았다.
  (`gboard/single-instance` 브랜치)

## 확인해야 하는 것

- 설치형 앱은 이제 여러 차례 실제로 켜서 확인했고, 그 과정에서 나온
  문제(창 권한이 빠져 앱이 안 닫히고 전자칠판이 안 열리던 것, 전자칠판이
  보조 모니터에 갇히던 것, 저장 실패가 화면에 안 보이던 것)는 각각 찾아서
  고쳤다. 다만 **단일 인스턴스 동작 자체**는 아직 사람이 눈으로 확인하지
  않았다 — 아이콘이 이미 떠 있는 상태에서 한 번 더 눌렀을 때 창이 두 개가
  아니라 하나만 뜨고 그 창이 앞으로 나오는지는, 에이전트가 GUI 인스턴스를
  두 개 띄워 눈으로 볼 수 없어 확인이 안 된 채로 남는다.
  `docs/gboard-first-run.md`의 사람 확인 목록에 줄을 추가해 뒀다.

## 받아들이고 넘어가는 것

- 코드 서명이 없어 윈도우가 "알 수 없는 게시자" 경고를 띄운다. 1판에서는
  의도한 것이고, `docs/gboard-first-run.md`의 안내로 넘긴다.

## 사람이 눈으로 봐야 하는 것

자동 검사가 끝까지 못 보는 자리다. 설치본을 남에게 내보내기 전에 한 번씩
직접 확인한다.

- 앱을 켜면 `G-board` 제목의 창이 뜨고, 1024×700보다 작게 안 줄어든다
- 학급을 만들고 앱을 껐다 켜면 그대로 남아 있다
- 전자칠판이 두 번째 모니터에 전체 화면으로 뜨고, 닫으면 사라진다
- 앱을 종료하면 두 창이 함께 닫힌다
- **아이콘이 이미 떠 있는 상태에서 한 번 더 눌렀을 때 창이 하나만 뜨고
  그 창이 앞으로 나온다** — 단일 인스턴스 잠금. 에이전트가 GUI 인스턴스를
  두 개 띄워 볼 수 없어 아직 확인이 안 된 채로 남아 있다
- 급식·시간표·'지금' 카드·날씨가 실제 학교 자료로 맞게 뜬다
- 테마 넷이 각각 읽히고, 또렷하게가 프로젝터에서 실제로 또렷하다
- 백업 파일이 다운로드 폴더에 실제로 저장된다

`docs/gboard-first-run.md`는 **받으시는 분용**이다. 이 목록은 거기 두지
않는다 — 만드는 사람이 확인할 것과 쓰는 분이 읽을 것은 독자가 다르다.
