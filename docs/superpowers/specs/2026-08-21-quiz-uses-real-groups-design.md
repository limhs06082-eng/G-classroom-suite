# 퀴즈가 진짜 모둠을 쓴다

**날짜** 2026-08-21
**적용 대상** `features/quiz`
**계기** 두 앱을 합치면서 비로소 가능해진 것

---

## 1. 왜 지금인가

퀴즈 팀은 `1모둠~4모둠`이라는 **글자 넷**에서 시작했다. 자리·모둠에서 편성한
`Group[]`이 바로 옆에 있는데도 쓰지 못한 이유는 하나뿐이다 —
**두 앱으로 나뉘어 있어서 서로의 자료를 볼 수 없었다.**

합쳤으니 이제 볼 수 있다.

---

## 2. 팀은 세 곳에서 온다

```ts
resolveTeams(manual, groups) → { teams, source }
```

| 순위 | 출처 | 언제 |
|---|---|---|
| 1 | `manual` (`SuiteData.quizTeams`) | 교사가 직접 정했을 때 |
| 2 | `groups` (자리·모둠에서 편성한 것) | 직접 정한 것이 없고 모둠이 있을 때 |
| 3 | `DEFAULT_TEAMS` | 둘 다 없을 때 |

**직접 정한 것이 이긴다.** 남녀 대항이나 두 팀 대결처럼 모둠과 다르게 나누고
싶을 때가 있고, 그때 앱이 모둠으로 되돌리면 교사가 싸워야 한다.

**모둠은 살아 있는 값이다.** 복사해 두지 않는다. 자리·모둠에서 모둠을 하나
더 만들면 퀴즈에도 바로 나타난다. 복사하면 "왜 6모둠인데 퀴즈는 4개지"가 생긴다.

---

## 3. 진행 중에는 얼어 있다

`QuizRun.teams`가 시작 시점의 팀을 담는다. 이미 그렇게 돼 있고 그대로 둔다.

**`correctTeamsByQuestion`이 팀을 이름으로 담기 때문이다.** 퀴즈를 돌리는
도중에 모둠 이름이 바뀌면 앞 문제에서 맞힌 기록이 어느 팀 것인지 알 수 없게 된다.

---

## 4. 화면

모둠 설정 카드에 지금 무엇을 쓰는지 적는다.

| 출처 | 문구 |
|---|---|
| 모둠 | `자리·모둠에서 편성한 6모둠을 씁니다.` |
| 직접 | `직접 정한 팀을 씁니다.` + `모둠 쓰기로 되돌리기` 버튼 |
| 기본 | `아직 모둠이 없어 기본 팀을 씁니다.` + 자리·모둠으로 가는 링크 |

`모둠 쓰기로 되돌리기`는 `quizTeams`를 비운다. 그러면 §2의 순위가 다시 2번을 고른다.

---

## 5. 테스트

- 직접 정한 것이 있으면 그것을 쓴다 (모둠이 있어도)
- 직접 정한 것이 없고 모둠이 있으면 모둠 이름을 쓴다
- 둘 다 없으면 기본 팀
- 모둠 이름이 비어 있거나 겹치면 다듬는다
- 모둠이 하나뿐이어도 깨지지 않는다
- 어디서 왔는지(`source`)를 함께 알린다
