# 디자인 기본기 다듬기 설계

**날짜** 2026-08-14
**적용 대상** `G-classroom-suite`, `G-teacher-toolkit` 두 저장소 모두
**계기** 스쿨보드(호똑쌤) 분석 — [`../../reference/schoolboard-analysis.md`](../../reference/schoolboard-analysis.md)

---

## 1. 무엇을 고치나

임한솔이 스쿨보드를 설치해 보고 디자인 완성도 차이를 지적했다.
네 가지가 모두 어설프게 느껴진다고 했다: **글자체와 글자 크기 · 여백과 정렬 ·
색과 그림자·테두리 · 움직임과 반응.**

### 1.1 원칙 — 화려하게가 아니라 일관되게

스쿨보드가 완성돼 보이는 이유는 화려해서가 아니라 **같은 것이 항상 같은 모양**이기
때문이다. 우리 앱은 화면마다 여백과 크기가 조금씩 다르다. 그것이 "덜 만든 것 같다"는
인상의 실체다.

교사용 도구는 수업 중에 켜 놓는 물건이라 조용해야 한다.
목표는 **눈에 띄는 장식이 아니라 눈에 안 띄는 규칙**이다.

### 1.2 지금 상태 (실측)

| 항목 | 확인한 값 |
|---|---|
| Pretendard | 폰트 스택 맨 앞에 선언, **실제 로드 없음**(`document.fonts.size === 0`) |
| 본문 크기 | `text-sm` 246곳 — **이미 일관됨** |
| 보조 크기 | `text-xs` 32곳 — 일관됨 |
| 제목 크기 | `text-xl` 17 · `text-lg` 8 · `text-2xl` 5 · `text-3xl` 1 — **어긋남** |
| 버튼 높이 | `h-10` 63곳 · `h-11` 1곳 · `h-12` 2곳 |
| 그림자 | `shadow-sm` 6 · `shadow-lg` 3 · `shadow-xl` 2 — 카드에는 없음 |
| 다크모드 | 0곳 |
| 카드 안쪽 여백 | `p-4` 고정 (양쪽 저장소 동일) |

## 2. 폰트

`pretendard` npm 패키지의 **동적 서브셋**을 쓴다.
한글 UI는 실제로 쓰는 글자만 내려받아 60~100KB면 된다.

CDN을 쓰지 않는 이유가 둘이다.

1. 학교 네트워크가 외부 CDN을 막는 일이 잦다.
2. `index.html`의 CSP에 외부 호스트를 열어야 한다.

번들에 넣으면 오프라인에서도 그대로 뜨고, **fork 직후 설정 없이 동작한다**는 원칙과 맞는다.

전자칠판은 멀리서 읽어야 하므로 굵기 700~800이 실제로 로드되는지 확인한다.

진입 경로는 `pretendard/dist/web/variable/pretendardvariable-dynamic-subset.css`를 기대한다.
**설치 직후 이 파일이 실제로 있는지 확인한다.** 패키지 구조는 버전마다 다를 수 있고,
없으면 `dist/web` 아래에서 `dynamic-subset`이 붙은 CSS를 찾아 쓴다.

## 3. 타이포

### 3.1 크기 값을 한글에 맞게 재정의한다

본문은 이미 `text-sm` 246곳으로 일관되므로 **클래스를 갈아엎지 않는다.**
Tailwind 4의 `@theme`에서 **크기 값 자체**를 재정의해 246곳이 한 번에 좋아지게 한다.

```css
@theme {
  /* 한글은 라틴보다 x-height가 커서 같은 px에서 더 빽빽해 보인다. 한 단계 키운다. */
  --text-xs: 0.8125rem;   /* 13px */
  --text-xs--line-height: 1.55;
  --text-sm: 0.9375rem;   /* 15px — 본문 */
  --text-sm--line-height: 1.6;
  --text-base: 1rem;
  --text-base--line-height: 1.6;
}
```

위험이 1/10이고 효과는 같다. 300곳을 새 토큰으로 옮기다 하나를 빠뜨리는 쪽이 더 나쁘다.

### 3.2 어긋난 제목 31곳만 정리한다

`text-lg`·`text-xl`·`text-2xl`·`text-3xl`이 화면마다 다른 뜻으로 쓰이고 있다.
두 가지로만 남긴다.

| 쓰임 | 클래스 |
|---|---|
| 화면 제목 (페이지마다 하나) | `text-xl font-bold` |
| 카드·구역 제목 | `text-base font-semibold` |

카드 제목은 본문(15px)과 1px밖에 차이 나지 않는다. **위계를 크기가 아니라 굵기로 만든다.**
빽빽한 업무 화면에서 제목마다 크기를 키우면 화면이 시끄러워진다.

`text-2xl`·`text-3xl`은 홈의 요약 숫자처럼 **수치를 크게 보이는 자리**에만 남긴다.

### 3.3 자간과 숫자

- 본문 자간 `-0.01em`. 한글은 라틴용 기본 자간에서 벌어져 보인다.
- **숫자에 `tabular-nums`.** 지금은 모둠 점수가 `0점 → 10점`이 되면 버튼 너비가 튄다.
  점수·표·시간처럼 바뀌는 숫자에 적용한다.

## 4. 여백

### 4.1 어긋난 것만 정리한다

실측 결과 간격은 이미 대체로 모여 있다.

```
gap-2 126 · gap-3 73 · gap-1 61 · gap-4 35 · gap-5 5 · gap-0 5 · gap-6 4 · gap-8 1
```

`gap-1`(61곳)은 뱃지·아이콘처럼 **한 덩어리 안**에서 쓰는 정당한 값이므로 남긴다.
정리 대상은 **어디에도 속하지 않는 15곳**뿐이다.

| 지금 | 바꿀 값 |
|---|---|
| `gap-5` (5곳) | `gap-4` |
| `gap-6` (4곳) · `gap-8` (1곳) | `gap-4` |
| `gap-0` (5곳) | 뺀다 (기본값) |

쓰는 단계는 이렇게 굳힌다: `gap-4` 섹션 사이 · `gap-3` 카드 안 묶음 ·
`gap-2` 한 줄 안 · `gap-1` 한 덩어리 안.

### 4.2 안쪽 여백은 컴포넌트가 정한다

카드·모달·빈 상태의 안쪽 여백을 공통 컴포넌트에서 고정하고,
화면이 개별로 덮어쓰지 못하게 한다. 카드는 지금 `p-4`로 이미 고정돼 있으니 유지하고,
모달·빈 상태를 같은 규칙으로 맞춘다.

### 4.3 버튼 높이는 두 종류

`h-10`(기본)과 `h-11`(터치·칠판)만 남긴다. `h-12` 2곳을 정리한다.

## 5. 표면 — 색·테두리·그림자

### 5.1 그림자 두 단계

지금 카드에 그림자가 없어 배경과 붙어 보인다. 토큰을 **두 개만** 둔다.

```css
@theme {
  /* 배경에서 살짝 떠 보일 정도. 교사용 도구는 화려하면 안 된다. */
  --shadow-card: 0 1px 2px oklch(0.2 0.02 250 / 0.04), 0 1px 3px oklch(0.2 0.02 250 / 0.06);
  /* 진짜 떠 있는 것 — 모달·토스트 */
  --shadow-raised: 0 4px 6px oklch(0.2 0.02 250 / 0.05), 0 10px 20px oklch(0.2 0.02 250 / 0.08);
}
```

기존 `shadow-sm`·`shadow-lg`·`shadow-xl` 11곳을 이 둘로 옮긴다.

### 5.2 테두리는 건드리지 않는다

처음에는 테두리를 진하게 하려 했으나, 실측해 보니 이미 `slate-300`이 84곳으로
가장 많고 `slate-200`은 48곳이다. 옅지 않다.

**경계가 약해 보이는 원인은 테두리가 아니라 그림자가 없는 것**이다.
그림자와 테두리를 동시에 올리면 과해진다. 그림자만 넣고 테두리는 그대로 둔다.
넣어 보고도 약하면 그때 다시 본다.

### 5.3 기능색 토큰 이름을 바로잡는다 — toolkit만

`G-teacher-toolkit`의 `navigation.ts`가 수업 진행에 `seating` 색,
형성평가에 `duty` 색, 업무에 `assignment` 색, 문구에 `reward` 색을 쓴다.
1단계 저장소에서 복사하며 토큰 이름만 남은 것이다.

지금은 색이 맞아 보여도, 나중에 누가 "당번 색을 바꾸자"며 고치면 엉뚱한 화면이 바뀐다.
toolkit의 토큰을 그 저장소의 실제 기능 이름으로 바꾼다.

| 지금 | 바꿀 이름 |
|---|---|
| `seating` | `lesson` |
| `duty` | `quiz` |
| `assignment` | `task` |
| `reward` | `message` |

색 값(oklch)은 그대로 둔다. 화면은 바뀌지 않고 이름만 맞아진다.
`G-classroom-suite`는 이름과 실제가 이미 맞으므로 **건드리지 않는다.**

## 6. 움직임

토큰을 두고 전부 그것만 쓴다.

```css
@theme {
  --duration-fast: 120ms;
  --ease-out-soft: cubic-bezier(0.2, 0, 0, 1);
}
```

- 버튼: hover 시 배경, 누를 때 `active:scale-[0.98]`
- 모달·토스트: 짧은 페이드 + 4px 올라오기
- 탭: 밑줄 이동

`prefers-reduced-motion`으로 끄는 규칙이 이미 있고 그대로 둔다.
새로 넣는 전환도 그 규칙에 걸리도록 `transition`·`animation`만 쓰고
JavaScript 애니메이션은 도입하지 않는다.

## 7. 검증

### 7.1 제가 확인할 수 있는 것

- Pretendard가 실제로 로드되는지 (`document.fonts` 검사)
- 계산된 여백·행간·그림자 값이 토큰과 맞는지
- 남아 있는 `text-2xl`·`text-3xl`·`h-12`·`shadow-lg` 등이 의도한 자리뿐인지 (정적 검사)
- 두 저장소 각각 `npm run verify` (타입 검사 → 테스트 → 빌드)

### 7.2 임한솔이 봐 주셔야 하는 것

**이 환경에서는 스크린샷이 찍히지 않는다.** 브라우저 패널이 화면에 표시되지 않아
프레임을 만들지 못한다. 그래서 "실제로 나아 보이는가"는 확인할 수 없다.

각 단계가 끝나면 `npm run dev`로 직접 보고 어색한 곳을 알려 주셔야 한다.
이 부분은 대신할 수 없다.

### 7.3 회귀 위험

기존 테스트 505개(suite 320 + toolkit 185)는 클래스 이름을 거의 보지 않는다.
색 토큰 이름을 바꾸는 §5.3은 클래스 문자열이 바뀌므로,
바꾸기 전에 `seating|duty|reward|assignment`를 쓰는 자리를 전부 세어 두고
바꾼 뒤 같은 수가 나오는지 확인한다.

홈 레이아웃 재구성 · 카드 보이기/숨기기 · 애니메이션 라이브러리 도입.
