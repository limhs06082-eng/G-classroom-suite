# G-board 설계

## 무엇을 만드나

교실 컴퓨터에 설치해서 **하루 종일 켜 두는** 프로그램. 이름은 **G-board**.

받아 가시는 선생님이 할 일은 설치 파일을 받아 더블클릭하는 것뿐이다.
계정도, 콘솔도, 설정값도 없다. 자료는 그 컴퓨터 안에만 있다.

**웹앱을 그대로 감싼 것이 아니다.** 첫 화면이 다르다. 웹앱의 홈은
"우리 반이 어떻게 돌아가고 있나"에 답하고, G-board의 홈은 **"지금 뭐 하지"**에
답한다. 하루 종일 켜 두는 프로그램이 답해야 할 질문은 후자다.

## 웹앱과의 관계

둘은 **따로 드리는 별개의 것**이다. 하나가 다른 하나를 대체하지 않는다.

| | 웹앱 (`G-classroom-suite`) | G-board |
|---|---|---|
| 받는 법 | fork | 설치 파일 |
| 준비 | `firebaseConfig.ts` 여섯 줄 | 없음 |
| 자료 | 클라우드 (여러 기기) | 이 컴퓨터 파일 |
| 첫 화면 | 학급 운영 요약 | **오늘 보드** |
| 급식·날씨 | 없음 (기술적으로 불가) | **있음** |
| 시간표 | **있음** | **있음** (교사가 짜 넣음) |
| 형성평가 | 있음 | 없음 |
| 대상 | 직접 손보실 분 | 그냥 쓰고 싶은 분 |

두 갈래를 오가는 길은 **설정 → 백업·복원**이다. 이미 있는 기능이다.

## 저 둘과 다르게 만드는 것

쌤핀과 스쿨보드를 살펴보고 정한 자리다. 좋은 것은 가져오되 같은 것을
만들지 않는다.

### 그들이 잘하는 것

| | 쌤핀 | 스쿨보드 |
|---|---|---|
| 규모 | 기능 20+, 쌤도구 28 | 위젯 12+ |
| 배치 | 위젯 모드 4종, 투명도, 항상 위 | 벤토 대시보드, 드래그·크기 조절 |
| 꾸미기 | — | 테마 20+, 파스텔, 프레임 없음 |
| 처음 | — | 학교 이름 검색 → 1분 |

### 우리가 다르게 가는 네 가지

**1. 고르는 가짓수를 줄인다.**
위젯을 드래그해 짜 맞추게 하면 우리 강점인 '오늘과 우리 반의 연결'이
흐트러진다. **하루의 흐름대로 고정 배치**하고, 대신 카드 하나가 **시간에
따라 스스로 바뀐다**. 아침엔 당번, 수업 중엔 지금 교시와 도구, 점심엔 급식,
하교 후엔 마감 과제. 선생님이 짜야 할 것이 없다.

테마도 같은 결이다. 스무 가지를 늘어놓고 고르게 하지 않는다. **넷**이고,
꾸미기가 아니라 **상황**으로 나눈다. 아래 '테마 넷' 절을 보라.

**2. 교사 화면만이 아니라 교실 화면까지 다룬다.**
쌤핀도 스쿨보드도 선생님 모니터 안에서 끝난다. G-board에는 이미 전자칠판
모드가 있다 — 별도의 글자 크기 체계(`--text-board-*`)까지 갖춘. 설치형이
되면 이것이 **두 번째 모니터(교실 화면)에 뜨는 별도 창**이 된다.
이름이 `board`인 이유가 여기 있다.

**3. 기능을 늘리지 않는다.**
쌤핀은 20+, 우리는 아홉이다. 늘리는 대신 **오늘과 잇는다.** 지금이 3교시면
그 자리에서 전자칠판·타이머·화면 가리개가 손에 닿고, 하교 시간이면 오늘
마감인 과제가 저절로 올라온다. 찾아 들어가지 않아도 되는 것이 기능이 많은
것보다 낫다.

**4. 처음에 한 가지만 묻는다.**
스쿨보드는 학교·지역·학급·기초시간표를 **시작하기 전에** 받는다. 우리는
막지 않고, 홈에서 빈 카드가 하나씩 유도한다. 학교 하나를 고르면 급식과
날씨가 함께 따라온다 — 지역을 따로 묻지 않는다.

시간표만은 예외로 교사가 짜 넣어야 한다. NEIS에서 받을 수 없다는 것을
확인했기 때문이고, 그 사정은 아래 '시간표는 NEIS에서 받지 않는다'에 적었다.

### 베끼지 않기 위해 하지 않는 것

- 위젯 드래그·크기 조절 (스쿨보드의 것)
- 투명도·프레임 없는 창·항상 위 (두 앱의 것)
- 도구 28종 나열 (쌤핀의 것)
- **테마 20종** — 넷만 한다. 아래를 보라.

이것들이 나쁘다는 뜻이 아니다. **그 자리는 이미 그들이 잘 채우고 있다.**

## 첫 화면 — 오늘 보드

```
┌──────────────────────────────────────────────────────────┐
│  8월 22일 금요일   ☁ 24°   3학년 2반 · 24명              │
├───────────────────────────┬──────────────────────────────┤
│  오늘 시간표              │  지금                        │
│    1  국어                │  ──────────────              │
│    2  수학                │  (시간에 따라 바뀌는 자리)   │
│  ▶ 3  수학   ← 지금       │                              │
│    4  사회                ├──────────────────────────────┤
│    5  체육                │  오늘 당번                   │
│                           │  칠판 김하나 · 우유 이두리   │
├───────────────────────────┼──────────────────────────────┤
│  오늘 급식                │  오늘 마감                   │
│  기장밥 / 된장국 /        │  독서록 · 3명 미제출         │
│  불고기 / 배추김치        │                              │
└───────────────────────────┴──────────────────────────────┘
```

**왼쪽은 오늘의 사실**이다. 바뀌지 않는다 — 시간표와 급식.
**오른쪽은 지금 할 것**이다.

### '지금' 카드 — 하나만 시간을 따라간다

위치는 고정이고 **내용만** 바뀐다. 카드가 돌아다니면 선생님이 눈으로
다시 찾아야 한다.

| 때 | 무엇이 보이나 |
|---|---|
| 등교 전 (~8:40) | 오늘 당번, 오늘 일정. 조회에 필요한 것 |
| 수업 중 | `3교시 수학` + [전자칠판] [타이머] [화면 가리기] |
| 쉬는 시간 | 다음 교시 과목과 남은 시간 |
| 점심 (11:40~13:00) | 오늘 급식을 크게 |
| 하교 후 (14:30~) | 오늘 마감 과제, 미제출 명단 |

시간 구간은 **교사가 고칠 수 있다.** 학교마다 일과가 다르다. 기본값은
초등 일반 일과로 두고 설정에서 바꾼다.

### 교시 시각 — 일곱 줄을 다 받는다

```ts
/** 한 교시의 시각. 학교 것이지 학급 것이 아니다. */
export interface PeriodTime {
  period: number;   // 1 ~ 7
  start: string;    // "09:00"
  end: string;      // "09:40"
}
```

`SuiteData`에 `periodTimes: PeriodTime[]`로 붙인다. **`classId`가 없다** —
3학년 2반과 5학년 1반의 2교시 시작 시각이 다를 리 없다. 시간표가 학급마다
한 벌인 것과 다른 자리다.

시작 시각 하나와 수업·쉬는 시간 길이로 계산하지 않는다. 점심 앞뒤로
쉬는 시간이 들쭉날쭉한 학교가 많아 **5교시부터 어긋난다.** 일곱 줄을
다 받는 대신, 채워 둔 채로 준다.

| | 기본값 |
|---|---|
| 1~4교시 | 09:00 시작, 40분 수업, 10분 쉬는 시간 |
| 점심 | 12:10 ~ 13:10 |
| 5~7교시 | 13:10부터 같은 규칙 |

**빈 채로 두고 채우라고 하지 않는다.** 그러면 이 카드가 처음부터 안 뜬다.
틀린 학교는 고치면 되고, 고칠 곳이 어디인지는 카드가 알려 준다.

### 점심을 따로 묻지 않는다

일곱 줄 사이에서 **가장 긴 틈**이 점심이다. 12:10~13:10이면 60분이고
보통 쉬는 시간은 10분이다. 묻지 않아도 자료가 이미 말하고 있다.

한 가지를 더 묻지 않는 것이 이 판의 규칙이라 여기서도 지킨다.

### 도구는 새로 만들지 않는다

타이머도 화면 가리개도 **이미 있다.** `ToolsBar`가 화면 아래 전역 바로
늘 떠 있고, 전자칠판은 1판에서 별도 창이 됐다. 이 카드가 할 일은
**그것들을 그 자리에서 여는 것**뿐이다.

`ToolsBar`가 여는 상태를 자기 안에 들고 있어 바깥에서 열 길이 없다.
작은 context 하나로 올린다. 창 사이 신호(`gboard-write-error` 같은
`CustomEvent`)를 쓰지 않는다 — 그건 React 나무가 안 이어진 자리를 잇는
수단이고, 홈과 툴바는 둘 다 `AppShell` 아래라 이어져 있다.

### 1분마다 다시 그린다

'12분 남음'을 말하므로 분 단위로 깨야 한다. `useToday`가 자정에 한 번
깨는 것과 다르다. **초 단위 타이머는 안 쓴다** — 하루 종일 켜 두는
프로그램에서 1초짜리 타이머는 그 자체로 비용이다.

### 전자칠판을 어디서 여나

머리띠 오른쪽에 [전자칠판] 단추를 **항상** 둔다. 지금 교시가 무엇이든
한 번에 교실 화면을 띄울 수 있어야 한다. 무엇을 띄울지는 지금 열려 있는
기능을 따른다 (자리·당번·보상·과제·수업).

## 테마 넷

스쿨보드는 벚꽃·선셋·포레스트·네온처럼 **취향**으로 스무 가지를 준다.
우리는 넷이고 **상황**으로 나눈다. 교실 컴퓨터는 하루에도 조명이 바뀌고,
같은 화면이 프로젝터로도 나간다.

| 테마 | 언제 쓰나 | 바탕 |
|---|---|---|
| **밝게** | 기본. 교실 불을 켜 둔 보통 때 | 흰색 |
| **포근하게** | 종일 켜 두는 화면. 눈이 덜 시리다 | 크림빛 |
| **어둡게** | 불 끄고 영상 볼 때, 이른 아침 | 짙은 남색 |
| **또렷하게** | 프로젝터·전자칠판. 대비를 최대로 | 흰 바탕, 진한 글자 |

넷째가 우리 것이다. 전자칠판이 우리 강점이니 **교실 뒤에서도 읽히는**
테마가 있어야 한다. 꾸미기가 아니라 보이느냐의 문제다.

### 기능 색은 테마가 바꾸지 않는다

이게 이 설계의 규칙이다. 당번은 어느 테마에서나 초록, 자리·모둠은 파랑,
보상은 노랑이다. **선생님이 색으로 기능을 익힌 뒤에 테마를 바꿨다고
그 익힘이 무너지면 안 된다.**

테마가 바꾸는 것은 **바탕과 중립색**, 그리고 기능 색의 **명도**뿐이다.
색상각(hue)은 고정이다. 어두운 테마에서 `bg-duty-50`을 그대로 두면
거의 흰 카드가 되어 눈이 부시므로 명도만 낮춘다.

### 얼마나 큰 일인가 — 재어 봤다

화면 코드에 색을 직접 박아 쓴 곳이 **801군데**다. 전부 고쳐야 한다면
테마는 포기할 일이었다. 그런데 빌드된 CSS를 열어 보니 이렇다.

```css
.text-slate-600 { color: var(--color-slate-600) }
.bg-white       { background-color: var(--color-white) }
```

Tailwind 4는 값을 박지 않고 **변수를 가리킨다.** 변수만 덮으면 801군데가
함께 바뀐다. 브라우저에서 실제로 확인했다 — 머리줄이 흰색에서 어두운
색으로, 글자가 반대로 바뀌는 동안 **TSX는 한 줄도 안 고쳤다.**

색 변수는 모두 50개다. 테마 하나가 CSS 한 덩어리로 끝난다.

```
:root[data-theme='dark'] {
  --color-white:     ...   /* 표면색 */
  --color-slate-50   ~ 900 /* 중립 눈금을 뒤집는다 */
  --color-duty-50    ...   /* 기능 바탕만 명도 조정 */
}
```

### 실제로 재 보니 두 자리를 갈라야 했다

위의 '801군데'는 색을 쓴 **모든** 자리를 센 것이다. 그중 테마 때문에
실제로 손대야 하는 곳을 따로 세어 보니 훨씬 적었고, 대신 **한 변수가 서로
반대인 두 뜻으로 쓰이는 자리**가 둘 있었다. 그건 변수만 덮어서는 못 푼다.

**1. `bg-white`(표면 43곳)와 `text-white`(색깔 단추 위 글자 31곳)**

둘이 `--color-white` 하나를 쓴다. 어두운 테마에서 그 변수를 남색으로
덮으면 표면은 옳게 어두워지는데 `bg-brand-600 text-white` 단추의 글자까지
남색이 된다. 읽을 수 없는 단추가 서른한 개 생긴다.

그래서 `--color-surface`를 새로 두고 `bg-white` 43곳만 `bg-surface`로
옮긴다. `--color-white`는 이름 그대로 흰색으로 남는다. **801이 아니라
43이다** — 처음 어림한 것이 스무 배 컸다.

**2. `text-slate-900`(본문 글자)와 `bg-slate-900`(일부러 어두운 면)**

어두운 테마는 중립 눈금을 뒤집어야 글자가 읽힌다. 그런데 어두운 끝을
**배경으로** 쓰는 곳이 열 군데 있다 — 칠판 알약, PIN 자판, 잠금화면,
화면 커튼, 모달 뒤배경. 뒤집으면 전자칠판이 하얘진다.

이것들은 '중립 눈금의 어두운 끝'이 아니라 **어느 테마에서나 어두워야 하는
섬**이다. 그래서 그 여섯 뿌리에 `.ink` 한 자리를 붙여 **그 안에서만 어두운
팔레트를 고정한다.** 안에 든 색을 하나씩 고치지 않아도 되고, 밝은 테마에서는
섬으로, 어두운 테마에서는 바탕과 이어져 보인다.

> 남는 것은 이름과 뜻의 어긋남이 아니라 **뜻이 둘인 이름**이었다.
> 변수를 덮는 것으로 테마를 만들려면 그 둘을 먼저 갈라야 한다.

### 테마는 자료가 아니다

고른 테마는 그 컴퓨터의 취향이지 학급 자료가 아니다. 백업 파일에
들어가면 안 된다. 저장 위치는 아래 '자료 저장' 절을 보라.

## 처음 켰을 때 — 막지 않고 유도한다

**마법사를 띄우지 않는다.** 설치하고 켜면 홈이 그대로 뜬다.
아직 아무것도 없으니 카드들이 비어 있을 뿐인데, 그 빈 카드가
**무엇을 하면 채워지는지** 말한다.

```
급식 카드    "학교를 정하면 오늘 급식이 여기 나옵니다"    [학교 찾기]
시간표 카드  "시간표를 한 번 짜 두면 여기 나옵니다"       [시간표 짜기]
당번 카드    "역할을 만들고 배정하면…"                    [역할 만들기]
```

이건 새로 만드는 방식이 아니다. 지금 웹앱 홈이 이미 이렇게 한다
(`PendingNote` + `cta`). **그 패턴을 급식·시간표·날씨까지 넓히는 것**이다.

머리띠 아래에 얇은 띠 하나를 둔다 — `설정 3가지 중 1가지 마쳤습니다`.
다 되면 사라진다. 누르면 남은 것으로 간다. **닫을 수 있고, 안 해도 앱은 돈다.**

### 학교 찾기 — 코드를 묻지 않는다

지금 설정 화면은 시도교육청 코드와 학교 코드를 **직접 입력**하게 되어 있다.
그 코드를 아는 교사는 없다. 바꾼다.

```
"한빛초"  →  검색  →  인천한빛초등학교 (인천광역시교육청)
                      용인한빛초등학교 (경기도교육청)
                      위례한빛초등학교 (경기도교육청)
                            ↓ 고르면
              시도코드·학교코드·학교 이름·주소가 한꺼번에 채워진다
```

주소에서 시·군·구를 뽑아 좌표를 얻고, **날씨 지역까지 함께 정해진다.**
지역을 따로 묻지 않는다.

## 바깥에서 받아 오는 것

인증키는 필요 없다. 다만 **공짜에는 값이 붙어 있었다.**

| | 어디 | 열쇠 | 브라우저에서 | 확인 결과 |
|---|---|---|---|---|
| 학교 검색 | NEIS `schoolInfo` | 불필요 | **불가 (CORS)** | 찾히나 **다섯 곳만** |
| 급식 | NEIS `mealServiceDietInfo` | 불필요 | **불가** | 잘 나옴 |
| 시간표 | NEIS `elsTimetable` | 불필요 | **불가** | **쓸 수 없다** — 아래 |
| 날씨 | open-meteo | 불필요 | 가능 | 좌표로 조회 |
| 좌표 | open-meteo geocoding | 불필요 | 가능 | 시·군 이름으로 |

### 열쇠 없이 부르면 한 번에 다섯 행이다

2026-08-26에 직접 불러 확인했다. `pSize`를 얼마로 보내든 다섯 행이 오고,
`pIndex`로 쪽을 넘기면 **1쪽과 똑같은 다섯 행이 다시 온다.** 넘길 방법이 없다.

| 요청 | 전체 | 실제로 온 것 |
|---|---|---|
| `schoolInfo` `pSize=100`, "중앙초" | 88곳 | **5곳** |
| `elsTimetable` `pSize=1000`, 한 학교 하루 | 121행 | **5행** |
| `elsTimetable` `pIndex=2` · `pIndex=3` | — | **1쪽과 동일** |

기능마다 값이 다르다.

- **급식은 안 닿는다.** 하루치가 조식·중식·석식 최대 세 행이다. 실제로 재 보니
  보통 한 행(중식)만 온다. 2-가는 이 상한과 무관하게 옳다.
- **학교 검색은 닿는다.** 흔한 이름이면 다섯 곳만 보인다. 잘렸다는 말을
  화면에 띄우고 이름을 더 길게 넣으라고 안내한다. `PAGE` 상수도 5로 적는다 —
  20이라 적어 두면 코드가 거짓말을 한다.
- **시간표는 못 쓴다.** 아래.

> **CORS가 이 기능을 설치형 전용으로 만든다.** NEIS는 `Access-Control` 헤더를
> 주지 않아 브라우저에서 직접 부를 수 없다. Tauri는 Rust에서 요청하므로
> 그 제약이 없다. 웹앱에 급식·시간표를 넣으려면 중계 서버가 필요한데,
> 그건 "환경변수 없이 fork해서 바로"라는 웹앱의 전제를 깬다.
> **임의로 가른 것이 아니라 기술이 가른 자리다.**

### 어떻게 부르나 — `tauri-plugin-http`

`@tauri-apps/plugin-http`의 `fetch`를 쓴다. 이름은 표준 `fetch`와 같지만
**하는 일이 다르다.** 소스를 열어 확인했다.

```
invoke('plugin:http|fetch')
invoke('plugin:http|fetch_send')
invoke('plugin:http|fetch_read_body')
```

전부 IPC다. **webview는 NEIS에 직접 요청하지 않는다.** Rust가 대신
나가고 결과만 돌려준다. 그래서 CORS를 안 받는다.

### 그래서 CSP를 조일 수 있다

1판은 `app.security.csp`가 `null`이다. Tauri 문서상 이건 "느슨한 CSP"가
아니라 **CSP가 아예 없다**는 뜻이다. 지금은 번들 자산만 실어 방어할 만하지만,
학생 이름이 담긴 앱에 방어선이 한 겹도 없는 상태다.

바깥 요청이 전부 IPC로 나가므로 **CSP의 `connect-src`는 NEIS·날씨와
무관하다.** 조여도 기능이 안 깨진다.

```
default-src 'self';
connect-src 'self' ipc: http://ipc.localhost;
img-src 'self' data:;
style-src 'self' 'unsafe-inline';
font-src 'self' data:;
```

두 겹이 각자 다른 일을 한다.

| 겹 | 무엇을 정하나 |
|---|---|
| 플러그인 URL 범위 | **우리 앱이** 어디에 요청할 수 있는지 |
| CSP | **그 밖의 전부** — XSS가 생겨도 나갈 통로가 없다 |

`unsafe-inline`을 `style-src`에 두는 것은 감수한다. Tailwind와 React가
인라인 스타일을 쓰기 때문이고, 그걸 없애려면 화면 코드를 크게 흔들어야
한다. **`script-src`에는 절대 넣지 않는다** — 거기가 진짜 문이다.

정확한 값은 만들면서 맞춘다. 빈 화면이 뜨면 개발자 도구가 어느 지시어가
막았는지 정확히 알려 주므로, 조여 놓고 시작해 필요한 것만 연다.

### 어디까지 열어 줄 것인가

플러그인 권한은 호스트 단위로 잠근다.

```json
{
  "identifier": "http:default",
  "allow": [
    { "url": "https://open.neis.go.kr/*" },
    { "url": "https://api.open-meteo.com/*" },
    { "url": "https://geocoding-api.open-meteo.com/*" }
  ]
}
```

세 곳뿐이다. 우리가 부르는 곳이 그게 전부이므로 더 열 이유가 없다.

### 시간표는 NEIS에서 받지 않는다

처음에는 "나오나 빠진 교시가 있다"고 적어 두었다. 원인을 찾아보니
자료가 부실한 것이 아니라 **여섯째 행이 상한에 잘린 것**이었다.

```
서울중대부초 6학년 1반, 2026-08-26
  전체 = 6교시    받아 온 것 = 5교시
  1 국어 · 2 자율·자치활동 · 3 영어 · 4 수학 · 5 체육 · [6교시 없음]
```

한 학급만 콕 집어 물어도 다섯에서 끊긴다. 초등 5·6학년은 6교시가 예사라
**마지막 교시가 늘 사라진다.** 그리고 잘리는 자리가 하필 "지금 몇 교시지"를
가장 많이 보는 하교 직전이다. 조용히 틀리는 화면은 없느니만 못하다.

그래서 **교사가 한 번 짜 넣는다.** 초등 담임의 시간표는 학기 내내 거의
고정이고, 5일 × 6칸을 한 번 채우면 끝난다. 대신 얻는 것이 셋이다.

1. 잘리는 교시가 없다.
2. 수업을 바꾼 날 교사가 그 자리에서 고칠 수 있다.
3. **'지금' 카드가 말하는 "3교시 수학"이 항상 맞다.** 이 카드가 이 판의
   중심이라 여기가 틀리면 나머지가 다 의심스러워진다.

```ts
interface TimetableEntry {
  classId: string;
  weekday: number;        // 1(월) ~ 5(금)
  period: number;
  subject: string;
}
```

`source` 칸이 사라졌다. NEIS가 채워 주는 쪽이 없으니 덮어쓸 것도 없다.

열쇠는 `(classId, weekday, period)` 자연키다. id를 따로 두지 않는다 —
한 칸에 두 과목이 있을 수 없으니 id는 중복을 허용하는 구멍만 된다.
`SuiteData.timetableEntries`로 붙이면 `dutyRounds`·`scoreEntries`와 같은
모양이라 백업·복원·내보내기가 저절로 따라온다. `classId`로 묶이므로
**학기가 바뀌어 새 학급을 만들면 시간표도 새로 시작한다.**

교시는 1~7이다. 초등은 6교시가 최대인 학교가 많지만 7교시를 쓰는 곳이 있다.
**빈 칸은 '그날 그 교시가 없다'는 뜻**이라, 요일마다 교시 수가 몇인지 따로
묻지 않는다. 금요일에 넷만 채우면 금요일은 4교시다.

#### 짜는 화면 — 과목을 고르고 칸을 찍는다

35칸을 한 칸씩 눌러 고르게 하면 일흔 번 움직여야 한다. 뒤집는다.

```
설정 → 시간표                                    3학년 2반

  [국어] [수학] [사회] [과학] [영어] [체육] [음악] [미술]
  [도덕] [실과] [창체] [+ 직접 입력]
     ↑ 고른 과목이 도드라진다. 이제 칸을 찍으면 그것이 들어간다

         월      화      수      목      금
    1   국어    수학    국어    영어    국어
    2   수학    국어    수학    국어    수학
    3   사회    체육    과학    수학    체육
    4   과학    사회    영어    체육    창체
    5   체육    미술    음악    과학
    6           미술            도덕
    7

  빈 칸은 그날 그 교시가 없다는 뜻입니다. 찍은 칸을 다시 누르면 지웁니다.
```

과목 수만큼만 고르고 나머지는 찍기라 열둘 + 서른이다.

#### 과목 단추는 저절로 늘어난다

```
단추 = 기본 열하나  ∪  이 시간표에 이미 쓰인 과목
```

기본 목록은 고학년에 맞춰져 있다. 저학년은 `즐거운생활`·`바른생활`·
`슬기로운생활`을 쓰는데, NEIS에서 실제 자료를 받아 보고 확인한 사실이다.
한 벌로 두 쪽을 다 덮을 수 없다.

그래서 **직접 입력한 과목이 단추가 된다.** 저학년 담임이 `즐거운생활`을
한 번 치면 그 뒤로는 단추다. 전담·특수 과목도 마찬가지다. 기본 목록이
안 맞는 문제가 한 번의 타이핑으로 끝나고, 그 뒤로는 안 겪는다.

#### 홈 카드는 오늘 것만 세로로

`▶ 지금` 표시는 여기 없다. 그건 교시 시각(1교시 09:00~09:40)을 알아야
하는데 그것은 '지금' 카드의 몫이다. 여기서는 오늘 채워진 교시를 순서대로
보여 주는 데까지다.

| 형편 | 카드가 하는 말 |
|---|---|
| 시간표 없음 | "시간표를 한 번 짜 두면 여기 나옵니다" `[시간표 짜기]` |
| 주말 | "오늘은 수업이 없습니다" |
| 있음 | 오늘 채워진 교시를 순서대로 |

> **설계 원칙 하나를 여기서 굽힌다.** "처음에 한 가지만 묻는다"고 해 놓고
> 시간표를 묻게 됐다. 굽히는 대신 **막지는 않는다** — 시간표 카드는 빈 채로
> 뜨고 [시간표 짜기]를 권할 뿐이다. 안 채워도 앱은 돈다.

### 파일을 넷으로 가른다

무엇을 백업하느냐로 가른다. 급식과 날씨는 자료가 아니라 캐시고, 테마는
자료가 아니라 취향이다. 백업 파일에 지난주 급식이나 고른 테마가 섞이면 안 된다.

```
%APPDATA%\G-board\
  data.json      학급 자료 + 시간표 + 일과 시간   백업 O · 내보내기 O
  backups.json   되돌리기용 스냅샷                 백업 X
  prefs.json     테마, 창 크기·위치, NEIS 키       백업 X · 오래돼도 안 버림
  cache.json     급식, 날씨                       백업 X · 오래되면 버림
```

가르는 기준이 둘이다. **백업하는가**, 그리고 **오래되면 버리는가.**
prefs와 cache가 둘 다 백업 대상이 아니라고 한 파일에 담으면, 캐시를 비울 때
고른 테마가 함께 날아간다. 그래서 따로 둔다.

일과 시간(몇 교시가 몇 시부터인지)은 학교마다 다른 **사실**이라 자료 쪽이다.
새 컴퓨터로 옮겼을 때 다시 입력하지 않아도 된다.

급식은 최근 7일치를 남긴다. 학교 인터넷이 끊긴 날에도 오늘 급식이 보인다.
날씨는 1시간만 남긴다.

## 껍데기 — Tauri

| | Tauri | Electron |
|---|---|---|
| 설치본 | **~12MB** | ~290MB (쌤핀이 이 크기) |
| 화면 엔진 | 윈도우의 WebView2 | 크롬 동봉 |
| 최종 사용자 준비물 | 없음 (Win10 1803+ 기본 탑재) | 없음 |
| 바깥 API 호출 | **CORS 없음** | CORS 없음 |

웹 자산이 4.7MB이므로 설치본은 12MB 안팎. 빌드에 필요한 Rust와 Visual
Studio 2022 빌드 도구는 개발 컴퓨터에 이미 있다 (rustc 1.96.1 확인).

## 웹과 설치형을 가르는 방법 — 빌드 시점

```
npm run build          → 웹 (형성평가 O, 오늘 보드 X, LocalStorageAdapter)
npm run build:desktop  → 설치형 (형성평가 X, 오늘 보드 O, FileSystemAdapter)
```

`import.meta.env.VITE_TARGET`이 빌드 때 글자로 치환되어 안 쓰는 가지가
통째로 사라진다. 이 저장소에 이미 선례가 있다 — `router.tsx`가
`import.meta.env.DEV`로 개발용 갤러리 라우트를 지운다.

대안을 재어 보고 버린 것:

- *한 벌로 만들고 실행 중에 판단* — 설치형에 안 쓸 코드가 실린다.
  무엇보다 두 갈래를 시험으로 갈라내기 어렵다.
- *코드를 복제해 따로 관리* — 고칠 때마다 두 번 해야 한다.

### 형성평가를 빼는 이유

설치형에는 서버가 없어 학생 폰이 들어올 길이 없다. 반쯤 살려 두면
"되는 줄 알았는데 안 되는" 자리가 생긴다. 통째로 뺀다.

다만 사라진 것으로 보이면 안 된다. 설치형 홈에 안내 카드를 둔다 —
"형성평가는 웹에서 쓰실 수 있습니다" + 주소.

퀴즈 관련 자료 칸(`quizSets`, `quizResults`, `quizRun`, `quizTeams`)은
**스키마에서 빼지 않는다.** 두 갈래가 같은 백업 파일을 주고받아야 한다.

## 무엇이 안 바뀌나

```
안 바뀜  기능 논리 전부 — 자리 배치, 당번 배정, 점수 계산, 과제 판정…
안 바뀜  src/shared/domain(기존), ui, roster
안 바뀜  745개 테스트
```

`StorageAdapter`가 이미 저장 방식을 갈라 두었다. FirestoreAdapter를 넣을 때
기능 코드를 한 줄도 안 고쳤고, 파일 저장도 같은 자리에 들어간다.

**다만 `src/features/` 아래가 글자 그대로 안 바뀌지는 않는다.**

1. 전자칠판을 여는 여섯 곳의 `target="_blank"` → `openBoard()` 호출로
2. 홈은 설치형에서 **다른 화면**이 된다 (오늘 보드)

첫째는 자료가 아니라 화면을 어떻게 여는지에 대한 것이다. 둘째는 새 화면을
**더하는** 것이지 기존 홈을 고치는 것이 아니다. 웹앱 홈은 그대로 남는다.

## 자료 저장 — 어댑터가 아니라 그 아래를 바꾼다

계획을 짜며 찾은 것이다. 설계 초안은 `FileSystemAdapter`를 새로 만들려
했는데, `LocalStorageAdapter`가 `Storage`에서 쓰는 것은 **`getItem`·
`setItem`·`removeItem` 셋뿐**이었다. 그렇다면 어댑터를 새로 쓸 것이 아니라
**파일로 뒷받침하는 `Storage`**를 만들어 지금 어댑터에 끼우면 된다.

```
SuiteDataProvider
   └ LocalStorageAdapter          ← 그대로. 445줄, 시험 25개
        └ Storage
             ├ window.localStorage   (웹)
             └ FileBackedStorage     (설치형) ← 새로 만드는 것은 이것뿐
```

깨진 파일이면 백업으로 되돌리기, 자동 백업 간격 10분, 보관 정책
(`backup.ts` 107줄) — **이미 시험을 통과한 552줄을 그대로 물려받는다.**
새 어댑터를 쓰면 그 전부를 다시 쓰고 다시 시험해야 한다.

### 동기와 비동기를 잇는 법

`Storage`는 동기고 파일은 비동기다. 그 사이를 이렇게 잇는다.

```
켤 때    파일을 읽어 메모리 지도를 채운다        (한 번, 비동기)
읽기     메모리에서 곧바로 답한다                (동기)
쓰기     메모리를 고치고 파일 쓰기를 예약한다    (동기 → 비동기)
```

쓰기를 예약하는 이유는 저장이 몰아치기 때문이다. 보상 점수는 수업 중
분당 여러 번 눌린다. 매번 파일을 쓰면 디스크가 쉬지 않는다. **200밀리초
안에 온 쓰기를 묶어 한 번에** 내보낸다.

창을 닫을 때는 예약된 것을 반드시 흘려보낸다(`flush`). 이걸 빠뜨리면
마지막 몇 초가 사라진다.

### 열쇠와 파일의 대응

```
classroom-suite:v1:data      →  data.json      백업 O · 내보내기 O
classroom-suite:v1:backups   →  backups.json   백업 X
classroom-suite:v1:meta      →  prefs.json     백업 X · 안 버림
classroom-suite:v1:neis-key  →  prefs.json     (같은 파일 안)
```

백업을 폴더가 아니라 한 파일에 담는다. 초안은 `backups\` 폴더에 스냅샷을
하나씩 두려 했지만, 그러면 `LocalStorageAdapter`의 백업 논리를 못 쓴다.
되돌리기는 앱 화면(설정 → 백업·복원)에서 하지 폴더를 뒤져서 하지 않으므로,
사람이 폴더를 보기 좋은 것보다 **시험을 통과한 논리를 쓰는 편**이 낫다.

### 반쪽 파일을 만들지 않는다

`localStorage.setItem`은 통째로 성공하거나 실패한다. 파일 쓰기는 다르다 —
쓰는 도중에 앱이 죽으면 반쯤 쓰인 파일이 남고, 그건 JSON도 아니다.
한 해치 학급 자료가 그렇게 사라진다.

```
1. data.json.tmp 에 쓴다
2. 다 썼으면 data.json 으로 이름을 바꾼다   ← 운영체제가 쪼갤 수 없는 한 동작
```

어느 순간에 죽어도 남는 것은 옛 파일 아니면 새 파일이지 반쪽짜리가 아니다.

### 백업

지금 `LocalStorageAdapter`의 규칙(자동 백업 최소 간격 10분, 하루가 바뀌면
즉시 한 번)을 그대로 쓴다. 버리는 기준만 바뀐다 — localStorage에서는
**공간이 모자라서** 버렸지만 파일에는 5MB 한계가 없다. 대신 **최근 20개**로
개수를 자른다. 무한정 쌓이면 폴더를 여신 선생님이 어느 것이 무엇인지 모른다.

### 시험할 수 있게

파일 시스템을 직접 부르면 테스트에서 못 돌린다. 작은 인터페이스로 감싼다.

```ts
interface FileStore {
  read(path: string): Promise<string | null>;
  writeAtomic(path: string, text: string): Promise<void>;
  list(dir: string): Promise<string[]>;
  remove(path: string): Promise<void>;
}
```

`TauriFileStore`가 실제 구현, 테스트는 `MemoryFileStore`를 끼운다 —
`LocalStorageAdapter`가 `MemoryStorage`로 시험받는 것과 같은 방식이다.

바깥 API도 같은 방식으로 감싼다. `SchoolInfoSource` 인터페이스를 두고
테스트에서는 **실제로 받아 둔 응답**을 되돌려 주는 구현을 쓴다. 인터넷과
NEIS 사정에 테스트가 매이면 안 된다.

## 전자칠판 — 두 번째 창

지금 여섯 곳이 `<Link target="_blank">`로 연다. 데스크톱에서 이 링크는
**앱 창이 아니라 크롬을 연다.** 그 크롬은 `%APPDATA%`의 파일을 볼 수 없어
빈 화면이 뜬다. 안 고치면 전자칠판 기능 전체가 죽는다.

```ts
// src/shared/window/openBoard.ts
export function openBoard(path: string): void
//   웹     → window.open(path, '_blank')
//   설치형 → 새 Tauri 창. 두 번째 모니터가 있으면 그쪽에 전체 화면으로
```

고칠 곳은 다섯 — `SeatingPage`, `DutyPage`, `RewardPage`, `AssignmentPage`,
`LessonPage`. 여섯 번째 `QuizPage`는 웹 전용이지만 한 벌이라 함께 바꾼다.
여기에 오늘 보드 머리띠의 [전자칠판] 단추가 더해진다.

### 두 창이 같은 자료를 보게 하기

브라우저는 `storage` 이벤트로 창끼리 알려 주지만 Tauri 창 둘은 각자 다른
webview라 그런 것이 없다. `StorageAdapter.subscribe()`를 Tauri의 창 간
이벤트로 채운다 — **이미 인터페이스에 있는 자리라 새로 만들 것이 없다.**

내가 보낸 이벤트가 나에게 되돌아오면 화면이 덜컥거린다. `FirestoreAdapter`가
쓴 것과 같은 방법으로 막는다 — 직전에 보낸 글자와 같으면 버린다.

## 배포와 자동 갱신

```
git tag v1.0.0 && git push --tags
          ↓
GitHub Actions (tauri-apps/tauri-action)
          ↓
GitHub Releases
  · G-board_1.0.0_x64-setup.exe
  · G-board_1.0.0_x64-setup.exe.sig
  · latest.json
```

정식 배포는 CI에 맡긴다. 매번 같은 환경에서 나오고 비공개 열쇠가 개발
컴퓨터를 떠나지 않는다. 개발 중에는 `npm run tauri dev`.

| 어디 | 무엇 |
|---|---|
| `latest.json` | `https://github.com/{소유자}/G-board/releases/latest/download/latest.json` |
| 공개 열쇠 | `tauri.conf.json`의 `plugins.updater.pubkey` |
| 비공개 열쇠 | GitHub Secrets `TAURI_SIGNING_PRIVATE_KEY` |

쓰는 것: `@tauri-apps/plugin-updater` + `tauri-plugin-updater`.
열쇠 생성: `npm run tauri signer generate`.
번들 설정: `bundle.createUpdaterArtifacts: true`.

> **비공개 열쇠를 잃으면 되돌릴 수 없다.** 새 열쇠로 서명한 갱신은 이미
> 깔린 앱이 거부한다. 쓰시던 모든 분께 새로 받으시라고 일일이 알려야 한다.
> **열쇠를 만드는 그 자리에서 비밀번호 관리자에 넣는다.**

### 코드 서명은 하지 않는다

쌤핀·스쿨보드 둘 다 안 하고 안내로 넘긴다. 인증서 값을 지금 치를 이유가 없다.
대신 **첫 실행 안내를 제대로 쓴다** — "알 수 없는 게시자"가 뜨면
`추가 정보 → 실행`. 받는 분이 처음 마주칠 화면이라 여기서 막히면 소용없다.

## 하지 않는 것

- **위젯 드래그·크기 조절, 투명도, 항상 위** — 그 자리는 이미 스쿨보드와
  쌤핀이 채우고 있다. 우리 강점이 아니다.
- **테마를 넷보다 늘리는 것** — 넷이 상황을 덮는다. 다섯째를 넣으려면
  '어떤 상황이 안 덮이는가'에 답이 있어야 한다.
- **macOS·리눅스** — 교실 컴퓨터는 윈도우다.
- **설치 없이 쓰는 단일 실행 파일** — 자동 갱신을 붙일 수 없다.
- **설치형에서의 기기 간 동기화** — 교실 컴퓨터 한 대가 전제다.
- **코드 서명** — 위 참조.
- **웹앱에 급식·시간표** — CORS 때문에 중계 서버가 필요하고, 그건 웹앱의
  전제를 깬다.
- **학사일정·구글 캘린더 연동** — 다음 판에서 판단한다. 지금은 급식·시간표·
  날씨로 충분히 크다.

## 1판이 가르쳐 준 것

실제로 설치해 세 차례 켜 보고 나서야 드러난 것들이다. 794개 시험과 번들
검사가 전부 초록불인 채로 셋 다 살아 있었다. **2판 계획은 이것을 전제로 짠다.**

### 권한은 기본이 '읽기만'이다

Tauri의 `core:default`가 주는 창 권한 28개는 전부 조회다 — `is-maximized`,
`available-monitors`, `title`. **상태를 바꾸는 것은 하나도 없다.** 그래서
`destroy`(창 부수기)도 `create-webview-window`(창 만들기)도 거부당했고,
앱이 안 꺼지고 전자칠판이 무반응이었다.

2판은 HTTP 플러그인을 새로 붙인다. **권한을 미리 열거하고, 빌드된
`gen/schemas/capabilities.json`에 실제로 들어갔는지 확인한다.** 문서를
믿지 말고 `gen/schemas/acl-manifests.json`을 직접 펼쳐 본다.

다만 **Rust에서 직접 부르는 것은 ACL을 안 지난다.** ACL 검사는
`tauri::ipc::Invoke`에 있어 webview가 `invoke`로 부를 때만 걸린다.
단일 인스턴스 콜백의 `unminimize`가 그래서 권한 없이 돌았다. 필요 없는
권한을 넣으면 앱의 노출면만 넓힌다.

### 웹에서 맞던 동작이 설치형에서 함정이 된다

전자칠판의 닫기가 `navigate(경로)`였다. 웹에서는 옳다 — 칠판이 새 탭이니
닫기는 곧 돌아가기다. 설치형에서는 **전체 화면 창이 앱 복제본이 되고
제목 표시줄도 X도 없어 갇힌다.**

2판에서 같은 결의 자리는 **바깥 API를 부르는 곳**이다. 웹에서는 `fetch`가
CORS에 막히고 설치형에서는 안 막힌다. 같은 코드가 두 환경에서 다르게
행동하는 자리마다 **어느 쪽이 기준인지 정하고 주석에 적는다.**

### 앱이 자기 자료 위치를 잘못 말하고 있었다

"이 브라우저에만 저장합니다", "브라우저 기록을 지우면 사라집니다" — 설치형에서
전부 거짓이다. 자료 크기 경고(1MB는 Firestore 한도), 계정·동기화 탭,
기존 앱에서 가져오기 탭도 설치형에서는 뜻이 없어 걷어냈다.

2판이 화면을 새로 만드는 판이므로 **새 문구를 쓸 때마다 두 환경에서
참인지 확인한다.** 시험은 늘 웹 대상으로 돌기 때문에 틀린 쪽 문장을
아무도 안 읽는다.

### 조용한 실패가 가장 비싸다

`destroy()`가 거부돼도, 창 만들기가 실패해도, 파일 저장이 실패해도 화면에
아무 표시가 없었다. `void`가 거부를 삼키고, 저장 실패 알림은 웹에서만
뜨는 경로에 있었다.

2판은 **바깥에서 자료를 받아 온다.** 인터넷이 끊기고, NEIS가 느리고,
학교가 자료를 안 올린 날이 반드시 온다. **실패를 화면에 드러내는 것을
기능과 함께 만든다** — 나중에 붙이지 않는다.

### 시험이 기다리는 척만 할 수 있다

`data-testid="ready"`를 첫 렌더부터 내걸면 `findByTestId`가 곧바로
통과한다. 자료 로드를 기다리는 줄 알았는데 아니었고, 기계가 바쁠 때만
드물게 깨졌다. 로드에 20ms를 넣자 옛 판은 9개 전부 실패했다.

2판은 비동기가 훨씬 많다 — NEIS 세 종류와 날씨. **무엇을 기다리는지
시험이 분명히 말하게 한다.**

## 세 판으로 나눈다

한 번에 다 하지 않는다. 각 판이 끝나면 손에 잡히는 것이 나온다.

**1판 — 내 컴퓨터에서 도는 G-board** ✅ 2026-08-24 마침
Tauri 껍데기, 파일 저장, 전자칠판 두 번째 창, 형성평가 분기, 단일 인스턴스
잠금까지. 설치본 5.1MB, 시험 794개. 실제로 설치해 세 차례 확인했고
`docs/gboard-first-run.md`의 사람 확인 목록을 전부 통과했다.

**2판 — 오늘 보드와 테마**
학교 검색, NEIS 급식·시간표, 날씨, `TodayPage`, '지금' 카드, 유도형 설정,
테마 넷.
끝나면 **이것이 G-board가 되는 판**이다. 여기까지가 제품의 얼굴이다.
테마를 여기 두는 까닭은 오늘 보드가 있어야 테마를 제대로 볼 수 있어서다 —
빈 화면에 색만 입혀 봐야 맞는지 알 수 없다.

1판에서 배운 것을 아래 '1판이 가르쳐 준 것' 절에 모았다. 2판 계획은
그것부터 읽고 짠다.

**3판 — 남에게 드릴 수 있는 G-board**
GitHub Actions, 서명 열쇠, 자동 갱신, 첫 실행 안내.
끝나면 설치 파일 주소를 드릴 수 있다.

순서를 바꾸지 않는다. 파일에 자료가 안 쌓이는데 오늘 보드를 얹어 봐야
소용없고, 오늘 보드가 없는데 배포부터 갖춰 봐야 드릴 것이 없다.
