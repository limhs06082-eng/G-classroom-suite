# 통합 과정에서 빠진 기능 점검

**점검일** 2026-08-14
**대상** 원본 10개 앱 → `G-classroom-suite` · `G-teacher-toolkit`
**계기** 임한솔이 자리·모둠에서 "교사 시점 전환"과 "학생별 특징 작성"이 없다고 지적

---

## 점검 방법

1. **모델에 필드가 있는데 화면이 한 번도 안 읽는 것** — 화면·기능 코드 49개 파일 자동 검사
   (`src/features` · `src/shared/roster` · `src/shared/setup` · `src/app`.
   도메인·저장 계층은 제외했다. 거기선 당연히 전부 쓴다.)
2. **원본 컴포넌트 이름 대조** — 5개 앱 88개 컴포넌트를 우리 코드와 하나씩 확인

## 결론

`G-teacher-toolkit`(2단계, 4개 앱)은 **깨끗하다.**
미사용 필드가 `schemaVersion` 하나뿐이고 그것은 저장 계층 전용이라 정상이다.

아래는 전부 `G-classroom-suite`(1단계, 5개 앱) 이야기다.

**왜 이렇게 됐나:** 모델은 원본 타입을 꼼꼼히 옮겼는데(그래서 `tags`·`nickname`·`fixedRoleId`가
살아남았고 `isGroupLocked`처럼 늘어난 것도 있다), 화면 이식은 "핵심 흐름"을 기준으로 해서
부가 화면이 누락됐다. **모델은 정적이라 빠뜨리면 눈에 띄고, 화면은 안 만들면 그냥 없는 것처럼 보인다.**

---

## A. 그릇은 있는데 뚜껑이 없는 것

저장·백업·복원이 이미 되고 있다. **입력 UI만 붙이면 기존 자료도 그대로 살아난다.**

| 기능 | 필드 | 원본 위치 |
|---|---|---|
| 학생 성별·특성 태그 | `SeatingProfile.gender` · `tags` | 자리 앱 `StudentManagerModal` |
| 학생 별명 | `RewardProfile.nickname` | 보상 앱 `SettingsView` (검색에도 쓴다) |
| 고정 역할 | `DutyProfile.fixedRoleId` | 당번 앱 `StudentManager` |
| 점수 주기 상세 설정 | `ScoreCycle.weeklyStartDayApplyMode` · `monthlyType` · `showLifetimeCumulative` | 보상 앱 `PeriodManagerModal` |
| NEIS 학교 코드 | `SchoolProfile.officeCode` · `schoolCode` | 대시보드 (급식·시간표 조회) |
| 학년·반 | `ClassRoom.grade` · `classNo` | 여러 앱 |
| 학기 보관 | `Term.archivedAt` | — |
| 목표 달성 시각 | `ScoreGoal.achievedAt` | 보상 앱 |

## B. 그릇도 없는 것 — 모델부터 만들어야 한다

**2026-08-14 기준 미착수.** A를 먼저 하기로 했다.

| 기능 | 원본에서 하던 일 | 우선순위 |
|---|---|---|
| **교사 시점 전환** | 자리표를 교탁에서 본 방향으로 뒤집기. 화면·인쇄·전자칠판 세 곳 | **높음** |
| **균형 모둠 편성** | 성별·특성 균형 배치. 우리는 `performRandomGrouping` 무작위만 있다 | **높음** |
| 자리표 저장·불러오기 | 배치를 이름 붙여 저장하고 나중에 꺼냄 | 중간 |
| 과제 표(Matrix) 보기 | 학생 × 과제 격자로 제출 현황을 한눈에 | 중간 |
| 과제 학생별 요약 | 학생 한 명의 전체 제출 이력 | 중간 |
| 빠른 점수 입력 | 연속 입력 패널. 수업 중 여러 명에게 빠르게 | 중간 |
| 목표 달성 축하 화면 | 공동 목표 달성 시 전체 화면 축하 | 낮음 |
| 교사 PIN 잠금 | 학생이 만지지 못하게 | 낮음 |
| 오늘의 명언 | 대시보드 카드 | 낮음 |

교사 시점 전환과 균형 모둠 편성이 높은 이유: 자리 배치는 교사가 가장 자주 쓰는 기능이고,
이 둘이 없으면 원본보다 확실히 못하다. 나머지는 없어도 수업에 지장이 없다.

## C. 오탐 — 이름만 다르고 있다

| 의심한 것 | 실제 |
|---|---|
| 당번 배정 이력 | `dutyRounds`로 지난 회차가 남고 `공정성` 탭에서 쓴다 |
| 보상 활동 로그 | `기록` 탭에 있다 |

## 점검에 쓴 스크립트

재점검이 필요하면 같은 방법을 쓴다. 인터페이스 필드를 뽑아
화면 코드에서 한 번도 안 나오는 것을 찾는 방식이다.
새 기능을 붙인 뒤 이 검사를 다시 돌리면 "만들다 만 것"이 드러난다.
