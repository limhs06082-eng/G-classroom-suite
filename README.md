# 우리 반 — 학급 운영 통합 앱

학생 명단을 **한 번만 등록하면** 자리배치·역할당번·활동보상·과제제출을 모두 그 명단으로 관리하는
교사용 웹앱입니다. 쌤동네 연수에서 만든 앱 5종을 하나로 합쳤습니다.

| 원래 앱 | 통합본 위치 |
|---|---|
| 우리 반 종합 대시보드 | 홈 · 수업 도구 툴바 |
| 자리배치·모둠 편성 도우미 | 자리·모둠 |
| 학급 역할·당번 관리판 | 역할·당번 |
| 학급 활동·보상 관리판 | 활동·보상 |
| 학생 자료·과제 제출 현황 정리기 | 과제 제출 |

---

## 무엇이 좋아지나

- **명단 한 번**: 예전에는 앱 4개에 같은 명단을 네 번 넣어야 했습니다.
- **모둠이 이어집니다**: 자리·모둠에서 만든 모둠을 활동·보상이 그대로 씁니다.
- **전자칠판 화면**: 기능마다 `전자칠판` 버튼이 있어 새 창으로 크게 띄웁니다.
- **키보드 단축키**: 어디서나 `?`를 누르면 단축키 목록이 뜹니다. 칠판은 `F`(전체 화면)·`Esc`(닫기).
- **행동특성 및 종합의견 초안**: 학생 한눈에에서 관찰 기록·칭찬·당번·과제·출결로 초안을 만들고, 고쳐서 나이스에 붙여 넣습니다. 학생 명단의 [행동특성 한 번에]에서는 서른 명을 한 화면에서 쓰고, 선생님 개인의 AI 키(Gemini·OpenAI·Claude)를 넣으면 AI가 초안을 씁니다 — 학생 이름은 보내지 않습니다.
- **자동 백업**: 되돌리기 어려운 작업 직전마다 앱이 알아서 직전 상태를 남깁니다.
- **학급 게시판**: 선생님의 Firebase를 연결하면 학생이 링크·QR로 들어와 건의함·칭찬 릴레이·자유 이야기에 글과 댓글을 씁니다. 아래 '학급 게시판' 절.

## 시작하기

### 그냥 써 보기

1. 첫 화면에서 **처음 설정 시작하기**
2. 학교·선생님 이름 → 학년도·학기·학급 → 학생 명단 붙여넣기
3. 끝. 모든 기능이 이 명단을 씁니다.

명단은 아래 어떤 형식이든 됩니다.

```
김가람          1,김가람          1 김가람          3학년 2반,1,김가람
이나래          2,이나래          2 이나래
```

엑셀에서 번호·이름 두 열을 복사해 붙여넣어도 됩니다. 읽지 못한 줄은 **몇 행이 왜 안 됐는지**
알려 주므로 조용히 빠지는 학생이 없습니다.

### 내 저장소로 가져가기 (연수생용)

1. 이 저장소 오른쪽 위 **Fork**
2. [Vercel](https://vercel.com)에 GitHub 계정으로 로그인 → **Add New Project** → fork한 저장소 선택
3. 설정을 바꾸지 말고 그대로 **Deploy**

환경변수나 추가 설정이 **필요 없습니다.** 배포되면 바로 쓸 수 있습니다.

`vercel.json`의 `rewrites`는 지우지 마세요. 이 앱은 주소가 여러 개인 단일 페이지 앱이라,
`/seating`·`/quiz` 같은 주소에서 새로 고쳤을 때 서버가 `index.html`을 돌려줘야 합니다.
없으면 새로 고침마다 404가 납니다.

## 자료는 어디에 저장되나

**이 브라우저 안에만** 저장됩니다(localStorage). 서버로 보내지 않습니다.

그래서 이 두 가지를 꼭 기억해 주세요.

> - 브라우저 기록·캐시를 지우면 **학급 자료도 함께 사라집니다.**
> - 다른 기기(집 노트북, 교실 PC)에서는 자료가 보이지 않습니다.

**설정 → 백업·복원**에서 파일로 내려받아 두세요. 홈 화면에도 14일마다 백업을 권하는 알림이 뜹니다.
내려받은 파일은 같은 화면의 `백업 파일 가져오기`로 어느 기기에서든 되살릴 수 있습니다.

여러 기기에서 함께 쓰고 싶다면 Firebase를 붙이면 됩니다.
→ [`docs/firebase-guide.md`](docs/firebase-guide.md)

### 예전 앱을 쓰던 분

**설정 → 기존 앱에서 가져오기**에서 원본 앱의 학생 명단을 옮길 수 있습니다.
원본 앱을 쓰던 **같은 브라우저**에서 열어야 합니다. 원본 자료는 지우지 않습니다.

## 학급 게시판 — 학생과 함께 쓰기 (Firebase 연결)

건의함 · 칭찬 릴레이 · 자유 이야기. 학생은 계정 없이 링크(QR)로 들어와 글과 댓글을 쓰고,
선생님은 앱 안에서 글을 숨기고 지웁니다. 설치형(.exe)과 웹 어디서나 됩니다.

자료는 **선생님이 직접 만든 Firebase 프로젝트**에만 저장됩니다. 이 앱을 만든 사람도 볼 수 없습니다.
무료 요금제(Spark)로 충분합니다. 화면을 열 때마다 최근 글 100개·댓글 300개까지 읽는데, 가득 찬 게시판을
30명이 하루 두 번 열어도 하루 읽기 한도(5만 번)의 절반 아래입니다. 보통 게시판은 그보다 훨씬 작습니다.

준비물은 구글 계정 하나, 걸리는 시간은 10분쯤입니다. 앱의 **설정 → 학급 게시판** 탭에도 같은 순서가 적혀 있습니다.

### 1. Firebase 프로젝트 만들기

1. [console.firebase.google.com](https://console.firebase.google.com) → **프로젝트 추가** → 이름은 아무거나(예: `우리반-게시판`) → Google 애널리틱스는 **사용 안 함**
2. 왼쪽 **빌드 → Firestore Database → 데이터베이스 만들기** → 위치 `asia-northeast3 (서울)` → **프로덕션 모드로 시작**
3. **빌드 → Authentication → 시작하기 → 로그인 방법** 탭에서 두 가지를 켭니다.
   - **익명** — 학생이 계정 없이 들어오는 방법
   - **이메일/비밀번호** — 선생님 계정

### 2. 웹 앱 등록하고 설정값 복사

1. 프로젝트 개요 옆 **⚙️ → 프로젝트 설정** → 아래로 내려 **내 앱 → 웹(`</>`)** → 닉네임 아무거나 → **앱 등록** (Firebase 호스팅은 설정하지 않습니다)
2. 나오는 코드에서 `const firebaseConfig = { ... };` 부분을 **통째로 복사**합니다. 값을 하나씩 옮겨 적을 필요가 없습니다.

### 3. 앱에 붙여 넣기

1. 앱 **설정 → 학급 게시판** 탭 → 붙여 넣고 **[저장]**
2. **[연결 확인]** — "연결됐습니다"가 나오면 됩니다. 아니면 무엇을 빠뜨렸는지 그 자리에서 알려 줍니다.
   - "익명 로그인을 켜지 않았습니다" → 1-3
   - "Firestore 규칙이 막았습니다" → 아직 4단계를 안 한 것입니다(정상). 4단계 뒤 다시 누르세요
   - "데이터베이스가 아직 없습니다" → 1-2

### 4. 규칙 붙여 넣기 — 건너뛰지 마세요

같은 설정 화면 아래 **[규칙 복사]** → Firebase 콘솔 **Firestore Database → 규칙** 탭에 붙여 넣고 **게시**.

이 규칙이 실제 자물쇠입니다. 게시판을 만든 선생님 계정만 글을 숨기고 지울 수 있고, 학생은 숨긴 글을
읽지 못하며, '선생님' 표시를 단 글은 선생님 계정만 쓸 수 있고, 로그인하지 않은 요청은 아무것도 못 합니다. 학생 이름이 담기는 자료이므로 반드시 넣으세요.

### 5. 게시판 만들기

1. 앱 내비 **학급 게시판** → **[계정 만들기]**로 선생님 이메일·비밀번호 계정을 만듭니다. 이 계정은 선생님의 Firebase 안에만 있습니다.
2. **[이 학급 게시판 만들기]** → 6자 코드와 학생 링크가 생깁니다.
3. **[링크 복사]**해서 학급 메신저에 보내거나, **[QR 보기]**로 칠판에 띄웁니다.

학생은 링크를 열고 이름(또는 별명)을 적으면 끝입니다. 앱 설치도 계정도 필요 없습니다.
한 번 들어온 폰은 다음부터 코드만 있는 주소(`/classboard/join/코드`)로도 들어옵니다.

### 알아 둘 것

- **설치형(.exe)에서 학생 링크는 공식 웹 배포 `https://g-classroom-suite.vercel.app`를 가리킵니다.**
  링크에 선생님의 설정값이 실려 가므로, 그 화면은 선생님의 Firebase에만 붙습니다.
  자기 Vercel 배포가 있으면 설정의 '학생 화면 주소'를 바꾸면 됩니다.
- **개인정보.** 학생 이름과 글이 선생님의 Firebase에 저장됩니다. 학교 지침에 따라 게시판의 **'별명만 받기'**를 켜세요.
  사진·파일·좋아요는 없습니다 — 없어도 건의와 칭찬은 되고, 있으면 운영 부담이 늘어납니다.
- **설정값은 비밀이 아닙니다.** Firebase 웹 설정은 공개를 전제로 만든 값이고, 자료를 지키는 것은 4단계 규칙입니다.
  다만 설정값은 이 컴퓨터에만 저장되고 백업 파일에는 들어가지 않습니다. 다른 컴퓨터에서는 다시 붙여 넣고
  같은 선생님 계정으로 로그인하면 같은 게시판이 보입니다.
- **읽기는 화면을 열 때와 [새로고침]을 누를 때만** 합니다(실시간이 아닙니다). 그래서 무료 한도가 남습니다.
- 웹 판의 '계정·동기화'(학급 자료를 여러 기기에서 쓰기, [`docs/firebase-guide.md`](docs/firebase-guide.md))와는 별개입니다.
  같은 프로젝트를 써도 되고 따로 만들어도 됩니다. 게시판은 `boards/` 아래만 씁니다.

### 막혔을 때

| 증상 | 확인할 것 |
|---|---|
| [연결 확인] "익명 로그인을 켜지 않았습니다" | 1-3 Authentication → 로그인 방법 → **익명** |
| [연결 확인] "Firestore 규칙이 막았습니다" | 4단계 규칙을 붙여 넣고 **게시**했는지 |
| [계정 만들기] "이메일/비밀번호 로그인을 켜지 않았습니다" | 1-3 Authentication → 로그인 방법 → **이메일/비밀번호** |
| 학생 화면 "주소가 올바르지 않습니다" | 링크가 잘린 채 전달됐습니다. [링크 복사]로 다시 보내거나 QR로 |
| 학생 화면 "게시판을 찾지 못했습니다" | 다른 학급 코드이거나 게시판을 지운 뒤입니다. 링크를 다시 보내기 |
| 학생이 글을 올리면 "규칙이 막았습니다" | 4단계 규칙이 최신인지(설정 화면의 것과 같은지). 글 1,000자·댓글 300자 한도 |
| 설치형에서 계속 "인터넷 연결을 확인해 주세요" | 앱이 0.21.0 이상인지(설정 → 백업·복원 맨 아래 판 표시). 학교 망이 `*.googleapis.com`을 막는지 |

## 개발

```bash
npm install
npm run dev
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run verify` | 타입 검사 → 테스트 → 빌드. **커밋 전에 이것부터** |
| `npm test` | 테스트만 |
| `npm run build` | 배포용 빌드 |

### 구조

```
src/
├─ app/          라우터·레이아웃·오류 격리
├─ shared/
│  ├─ domain/    학생·학급·모둠 등 공통 모델과 불변조건
│  ├─ storage/   저장·백업 (Firebase는 여기에 붙습니다)
│  ├─ roster/    명단 단일 원본
│  └─ ui/        공통 컴포넌트와 디자인 토큰
└─ features/     seating · duty · reward · assignment · home · tools
```

**기능 코드는 localStorage를 직접 부르지 않습니다.** 전부 `StorageAdapter`를 거칩니다.
Firebase를 붙일 때 이 경계 덕분에 화면 코드를 고치지 않아도 됩니다.

설계 배경과 판단 근거는 [`docs/superpowers/specs/`](docs/superpowers/specs/)에 있습니다.
